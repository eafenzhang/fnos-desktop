# 本轮优化：做了什么、为什么、怎么验证

日期：2026-11-16
基线：`0.3.12`（commit `2fb9cb1`）
范围：只改**代码与仓库机制**，不改产品行为、不改上游 vendored 资产。

---

## 一、P0（用户直接感知 / 排障底线）

### 1. release 版日志落盘 —— 新增 `src-tauri/src/logfile.rs`

**问题**：`main.rs` 的 `windows_subsystem = "windows"`（R9）让安装版没有控制台，全仓 60+ 处
`eprintln!("[fnos] …")` 在 NSIS 装出来的二进制里**全部丢失**。而它们恰好是白屏 / 加载失败 /
`window.open` 裁定 / 标签页创建失败 / 更新失败这些现场的唯一证据。

**做法**：
- 新增 `logfile` 模块，暴露 `flog!` 宏（语法与 `eprintln!` 完全一致）：**同时**写 stderr
  （debug 行为一字不变）与 `%APPDATA%\com.fnos.desktop\app.log`。
- 全仓 44 处 `eprintln!` 改为 `flog!`（commands / injector / updater）。
- 行格式 `YYYY-MM-DD HH:MM:SS.mmmZ [fnos] …`（UTC，24 字符定宽，便于排序 grep）；
  时间戳用 Howard Hinnant 的 `civil_from_days` 自算，**不引入任何新依赖**。
- 单文件上限 4 MiB，超了轮转为 `app.log.1`（磁盘占用恒 ≤ 8 MiB）；单条正文截到 8192 字符；
  换行折成空格（一条日志绝不变成两条）。
- 任何 IO 失败一律静默并放弃该 sink（排障设施不能把进程搞崩）；`FNOS_LOG=0/false/off` 可关。
- **测试进程不落盘**（`cfg!(test)` 直接返回 None）：否则跑单测会往真实配置目录写日志。

验证：3 项单测（开关取值表、固定宽度 UTC 时间戳含闰日、`civil_from_days` 已知点）。

### 2. 页面上报/探针通道加主标签归属门 —— `commands.rs::handle_title`

**问题**：`FNOSPROBE:` / `FNOSREPORT:` / `FNOSCHUNK:` 三条控制前缀只按前缀分流、**不看
webview 归属**。于是任意一个第三方应用标签页只要写一句
`document.title = 'FNOSPROBE:{"err":true,…}'`，宿主就 `mark_failed` → 整个主窗口被重建成
错误页，**所有标签一起消失**。上报同理：外部页可覆盖 `page_report` 槽位，让设置窗状态条
从「已注入」错乱。

**做法**：
- 三条前缀统一加 `label == MAIN_WINDOW` 门（`titlebar` 是本地资产页、`tab-*` 是外部应用页，
  都没有资格替主标签回话）。
- 顺带修 `on_load_probe` 的槽位泄漏：旧实现里「判定成功」那条路在 `probe_verdict` 返回
  `None` 时直接 `return`，`probe_generation` 永久停在 `Some`，同世代里任何迟到/伪造的回话
  都还能再走一遍 `mark_failed`。现在**先消费槽位、再分成功/失败**。

### 3. 标签页键盘快捷键 —— 新增 `src-tauri/inject/keys.js`

**问题**：T14d 把外部应用做成标签页（浏览器语义），但全仓搜不到 `keydown`——Ctrl+T /
Ctrl+W / Ctrl+Tab 全部落进页面、什么都不发生。

**做法**：焦点在子 Webview 里，tauri 的 `WindowEvent::KeyboardInput` 收不到；给 WebView2 装
`AcceleratorKeyPressed` 需要 `with_webview` + 裸 unsafe COM。本壳已有「页面 → 宿主」通道
（`document.title` 控制前缀，不占任何 IPC 授权），沿用它：
- 页面侧 `keys.js`：Ctrl+T → `new`、Ctrl+W → `close`、Ctrl+Tab → `next`、
  Ctrl+Shift+Tab → `prev`；写完 60ms 后把标题还回去（只在标题仍是我们写的控制串时）。
- 宿主侧 `commands.rs::handle_tab_key`：动作白名单（四个，其余静默丢弃）+ **120ms 冷却**
  （CAS 在 `last_key_at: AtomicU64` 上，不取任何 Mutex）。执行的仍是既有函数
  （`open_app_tab` / `tab_close` / `activate_tab`），**不新增任何权限**。
- 编辑区策略：`new` / `close` 在 input/textarea/contenteditable 里不抢（会瞬间丢表单）；
  `next` / `prev` 是纯导航，编辑区里也放行。
- 新增 `neighbor_tab` 纯函数（首尾环绕 / 单标签不动 / 当前标签不在表里不做事）。

验证：`tests/keys.test.mjs` 7 项（映射表、非白名单不吞键、编辑区策略、标题还原不覆盖页面
自己的标题、不堆定时器、诊断口）+ Rust 侧 2 项（`neighbor_tab` 边界、通道白名单与
「不得触达 set_config/reset_config/import_wallpaper/open_url」）。

## 二、P1（值得顺手修）

### 4. 更新器：sha256 校验 + 重入闸门 —— `updater.rs`

- **完整性**：`pick_installer_asset` 现在一并解析 GitHub 的 `assets[].digest`
  （严格只认 `sha256:` + 64 位十六进制）。下载完成后 `file_sha256` 比对，不匹配即删文件报错；
  `updates/` 里的同名文件复用前也要过同一道判定（此前只比体积 ≥ 1 MB，配了
  `updateMirrorPrefix` 时等于把一个可能被替换的 exe 直接静默执行）。老 release 没有 digest
  时退回体积判定并**在日志里如实标出来**。新增依赖 `sha2 = "0.10"`（已在 lock 里）。
- **重入**：托盘菜单项无法置灰，第一次下载（最长 120 秒）期间再点一次会并发下载 + 叠两个
  原生弹窗。`UpdateCheckGuard` 用 `AtomicBool` CAS 抢闸，`Drop` 释放；重复点击直接提示
  「正在检查 / 下载更新」。
- `.part` 临时名带进程 id（并发写不再互相截断）。
- 顺带把 `is_newer` 接回实际调用点（它此前只被测试调用，`#[allow(dead_code)]` 都不够——
  比较逻辑散在 `latest <= cur` 一行里，两处口径容易漂）。
- 修 `host_is_allowed_for_mirror` 的误伤：旧判定 `starts_with("fc")/("fd")` 会把
  `fcdn.example.com`、`fdroid-mirror.org` 这类**正常公网镜像域名**一并拒绝，现在只有含冒号的
  IPv6 字面量才做地址段判定。

验证：`sha256_digest_is_parsed_strictly`、`installer_reuse_requires_the_content_to_match`
（真文件 + 真哈希）、镜像前缀误伤/保留段各一组。

### 5. 复用登记表 `open_tabs` 的两处缺口 —— `commands.rs`

- **命中后复验页面**：旧实现只验「webview 还活着」。标签页是完整浏览器语义，用户可以在里面
  点链接跳走；旧逻辑会把「应用页跳走后再点同一入口」切到一个显示着别的内容的旧标签。
  现在命中后用 `wv.url()` 复算 `page_key`，不等就清条目照常新建。
- **重建时清空**：`build_main_window_with` / `build_error_window` 复位 `tabs` 时一并
  `open_tabs.clear()`（注释早就承诺了，代码没有）。
- **新标签初始标题**：`tab_initial_title` 取主机名第一段（`hermes-studio.…` → `hermes-studio`），
  IP 字面量整段保留，`about:blank` → 「新标签页」。此前新标签会显示内部 label（`tab-3`）
  直到页面报出 `document.title`。

### 6. `reset_config` 与 `set_config` 共用重建判据 —— `payload_changed`

旧 reset 只比 `injectEnabled` / `homeUrl` 两项，于是「恢复默认」把完美图标关掉、把登录壁纸
清空之后，活窗口的初始化脚本里仍带着已关闭的 1 MiB 图标与旧壁纸（设置窗说关了、页面还在生效，
直到下次重启）。现在抽成 `payload_changed(prev, next)`，两条入口共用，并加了
`payload_changed_covers_exactly_the_four_reload_keys` 正反例测试。

### 7. 初始化脚本缓存 —— `init_script_cached` + `injector::script_fingerprint`

`build_init_script` 每次都要读壁纸（≤ 8 MiB）、base64 15 个图标（≈ 1 MiB）、拼 ≈ 500 KB 文本。
它原先在**每开一个标签页**与每次建窗时都完整跑一遍。现在按内容指纹缓存进
`AppState::init_script`：指纹覆盖所有真正进脚本的键（inject / dock / keepalive / perfect /
wallpaper / mods / local），宿主私有键（homeUrl / nasUrl / window）**不进**指纹（它们变了
本来就不需要重建载荷）。锁纪律：只在锁内查/写，昂贵的构建在锁外。
验证：`script_fingerprint_covers_every_key_that_reaches_the_script`（7 个正向 + 3 个反向）。

### 8. 跨 DPI 显示器 —— `main.rs`

`WindowEvent::ScaleFactorChanged` 此前落进 `_ => {}`。子 Webview 的 bounds 按**物理**像素算，
tao 不保证换屏后再补一条 `Resized`，于是 32px 标题栏在 100% ⇄ 150% 之间拖动后会残留旧缩放的
条高。现在复用同一个 `relayout_main_window`。

## 三、仓库机制

### 9. CI 测试门禁 —— `.github/workflows/release.yml`

新增 `test` job（`npm test` + `cargo test --all-targets`），`build` job `needs: test`。
此前 129 项 Rust 单测 + 158 项前端契约测试只在本地跑，`git tag && git push` 直接出包——
测试红了也照样发。同时补了 `pull_request` 触发。

### 10. `ui/` 改动的重编译保证 —— `build.rs`

`generate_context!()` 在宏展开期读 `frontendDist`，而 `tauri-codegen` 不为同 crate 的资产目录
发 `rerun-if-changed`（`tauri-build` 只在 `Attributes::codegen(...)` + `tauri_build_context!`
那条路里发）。README 原来让人手动 `cargo clean -p` 或改 `main.rs` 时间戳——靠记性，会漏。
现在 build script 对 `../ui/settings` 整棵树发一条 `rerun-if-changed`，build script 重跑即带动
crate 重编。**已实测**：往 `settings.css` 追加一行探针 → `cargo build` 重新编译了本 crate
（55.91s → 17.14s 的增量编译，日志里出现 `Compiling fnos-desktop`），随后已还原该文件。

## 五、明确**没有**做的事

- **失败判定仍只覆盖首次导航**（页面内跳转失败不切错误页）：要改 `begin_load` 的世代语义，
  会牵动「连续失败次数只在成功时清零」的退避规则，属于需要单独验证的行为变更，本轮不动。
- **非 fnOS 页面仍会拿到完整注入载荷**（P0-2 的下一半）：按 origin 分档需要给
  `WebviewBuilder` 两套脚本并确认 `content-script.js` 的签名判定时序，风险高于收益，
  本轮只做了「同一份脚本不再重复构建」。
- **dock.js 的 S4 全量扫描**（`body *` + `getComputedStyle`，上限 2000 节点）：只在
  S1/S2/S3 全落空时走，且要求用户开了自动隐藏。改动它需要重做 `dock.test.mjs` 的
  11 个接管用例，收益（首帧偶发卡顿）低于回归风险。
- `_spike_tauri/`（19 个跟踪文件）与根目录探针报告仍在仓库里：属于清理动作，留给发版时
  单独做，避免本轮 diff 混进无关删除。
