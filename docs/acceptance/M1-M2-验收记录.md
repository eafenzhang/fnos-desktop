### 1.3 关于第 4 条的注入判定手段（重要）

用户的真实 NAS 只能用其凭据登录，controller 明确不索取。因此第 4 条用**本地页 + 真实上游链路**验证：

- 主探针页 `http://127.0.0.1:8791/index.html`：带 `data-fn-id`，且 origin 写入 `mods.enabledOrigins` → 命中上游 `content-script.js:2947` 的 `isWhitelisted` 分支（跳过 1.5s 探测）。

### 第 1 条：官网被正确跳过

**做了什么**

1. 真实官网（`enabledOrigins` 为空）：`homeUrl=https://fnos.net/` 启动，观察窗口与页面文本（`_t10-runtime.log:445-473`）。
   - 主窗口标题 = `FN Connect 远程访问 - 飞牛 fnOS`（生产代码 `commands.rs:253` 的 `on_document_title_changed` 把页面标题镜像为原生窗口标题）。
   - 应用标准错误：`[fnos] 主窗口页面已加载: https://fnos.net/`。
   - UIA 可读到的页面文本块（6 块）与官网一致：`FN Connect 远程访问 - 飞牛 fnOS`、`… - Web 端`、`FN Connect 远程访问组件…`、`Copyright © 深圳市…`、`粤ICP备…20230020469号-5` → 页面确实渲染的是官网本身。注：该次直读先打印了一行 `WARN no RootWebArea in the live window`（`_t10-runtime.log:460`），即这一轮没有走 RootWebArea 路径；但紧随其后仍从该窗口读到上述 6 块文本（`:461-467`），所以这 6 块是真实读数，只是取证路径带了这条告警。
2. 等价对照（同一份代码、同样的判定入口）：`/plain.html` 非白名单且无签名线索 → 页内自证 **6 秒内 `n_el=0`、`ms_first=never`、`mod_exec=false`、`css_var=none`、`mod_flags=0[]`、`up_err=undefined`**（`_t10-runtime.log:426-429`，原始行见 `_t10-server-8792.log`）。
   该页的 `boot` 行同时证明**注入载荷本身进了页面**（`shell=1`，`injectedBrand=#0066ff`）而**上游没有注入任何 mods 痕迹** —— 正是「官网被正确跳过」的机制。
3. 反向对照：把同一 origin 上的页面换成带 `data-fn-id` 的 `/sig.html`（仍不在白名单）→ **注入发生**：`n_el=8`、`ms_first=253ms`、`mod_exec=true`、`css_var=32px`（`_t10-runtime.log:436-438`）。说明「不注入」是**签名判定**的结果，而不是「这条路径从不注入」。
4. 代码层依据（**本条结论的唯一落地依据，日志 NOTE 亦只引用这一条**）：`content-script.js:2748` 的域名正则 `(\.fnos\.net)$` 要求前导点，根域 `fnos.net` 不命中。`hasFnOSSignature()` 的其余三个分支——`fnos-token`/`fnos-long-token` 存储、`fn-app`/`data-fn-id` DOM 标记、`/appcgi/` 资源（`content-script.js:2751-2771`）——在真实官网上的实况本轮**未观测**：`_t10-runtime.log:445-473` 内没有任何 cookie / 资源 / 标记检查，该日志自己的 NOTE（`:468-470`）也只把「官网无注入痕迹」的依据落在域名正则与本地 `/plain.html` 对照上。官网这三个分支是否都不命中，需按 §3 第 3 条用 F12 人工确认。

**为什么不能完全自动**：第三方站点（`fnos.net`）无法从外部注入观测脚本（生产代码只注入 mods 载荷），所以「页面上确实没有 `#fnos-ui-mods-*`」只能在等价本地页上直接证明。真实官网的**外观与浏览器一致**需要人工确认（步骤见 §3 第 3 条）。

### 4.1 测量方法

- 探针页在**解析期**即建立 `MutationObserver(document, {childList,subtree})` + 10ms 轮询；页内脚本把每次观测到的事件记成 `performance.now()`（相对于导航起点 `timeOrigin`）。

|---|---|---|---|---|---|---|
| 白名单路径 `/index.html`（`:8791`，命中 `enabledOrigins`） | **180** | 183 | 207 | 199 | 209 | 43 |

|---|---|

### 4.3 结论与局限（如实说明）

- 相对 spec §5.6 的「约 400KB/次导航」预算，实测载荷 **≈423KB，超出约 5%**。按组成拆开看：`content-script.js` 113KB（与 spec 一致）、`mod.js` 63KB（一致）、7 个 CSS **225.7KB vs spec 写的 ~218KB**（+3.5%），差额主要来自 CSS，且载荷是**每导航重新注入/解析**的（`initialization_script` 走 WebView2 的 `AddScriptToExecuteOnDocumentCreated`）。这是 spec 已知风险（§14「每次导航注入 ~400KB | 首屏变慢」）的**量化**，不是缺陷；是否要做「CSS 按需注入」由 controller 决定。
- **局限 1**：本地探针页是 ~1KB 的空白页（没有 fnOS 应用 DOM、没有 `appcgi` 资源），上述数字是**壳侧注入开销的下界**，不能当成真实 NAS WebUI 的首屏时间。
- **局限 2**：`ms_first` 受「页面最早可观测时刻 = 177ms」限制，只是上界；`initAt`（方案 C spike 的探针变量，`_spike_tauri/src-tauri/src/main.rs:34`）在 HEAD 上不存在，读数无法与它对照。
- **局限 3**：观测用 10ms 轮询 + MutationObserver 混合；MutationObserver 回调是微任务，触发即记录，抖动远小于 10ms，但 `ms_mod`/`ms_css` 可能被轮询粒度推迟 ≤10ms。
- **局限 4**（机制说明）：非白名单站点会先走 `waitForFnOSSignature(1500)` 的探测（`/plain.html` 上表现为 6 秒内始终不注入；签名很快命中的 `/sig.html` 只多花 ~70ms）。真实 NAS 若不在 `enabledOrigins` 里，首屏注入会相应晚 0–1.5s；把它加进白名单（设置窗保存 NAS 地址即自动并入）可跳过这段。

## 6. 附：可复用的判据与坑（给后续 T11/T13 验收）

1. **托盘菜单直读**：PowerShell 5.1 **不能**把 PS 函数返回的 IAccessible RCW 传给 `[A]::ChildCount()`（会拿到 `System.__ComObject` / `Object[]` 而抛转换错）。把 MSAA 遍历整体放进 C#（见 `_t10-stages.ps1` 的 `T10Acc.Dump`）一次即可拿到名字/状态/角色；`MN_GETHMENU(0x01E1)` + `GetMenuState` 还能拿到**OS 级勾选标志** `MF_CHECKED(0x8)` 与 `MF_SEPARATOR(0x800)`，比 MSAA 更接近"✓ 被画出来了"这一事实。
2. **菜单键盘导航**：`VK_DOWN` 只落在可选中的项上（跳过分隔符），所以"到达第 N 项"需要 `N - 分隔符数` 次 down，并且应当**每步回读 `accFocus` 断言**再回车（否则会像本轮一样点错项）。
3. **Chromium UIA 冷树**：任何"按 AutomationId/Name 找元素"的断言都应先轮询到 `nav`（或已知锚点）出现再开始判分，否则第一次查询可能返回空树。
4. **窗口标题当观测通道**：生产代码 `commands.rs:253` 注册了 `on_document_title_changed`，因此页面把测量结果写进 `document.title` 就能被 `EnumWindows` 读到（本轮用于 `PROBE|…` 通道）；更长的结果用同源 `fetch('/report')` 打到本地探针服务器落盘（页面侧无需任何生产代码改动）。
5. **`FNOS_DESKTOP_CONFIG_DIR`**（`paths.rs`）是隔离验收配置的官方开关，用它可以不碰用户真实配置目录。
6. **给应用发 `WM_CLOSE`** 即可验证 `closeToTray` 的关窗隐藏路径；**设置窗的 `WM_CLOSE` 会真的销毁窗口**（spec §7），随后可用托盘的「系统设置」重建（本轮已证：销毁 → 2s 内重建）。
